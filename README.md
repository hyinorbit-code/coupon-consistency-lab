# Coupon Consistency Lab

한정 수량 쿠폰의 발급·사용·취소·만료·정산을 소재로 **동시성 제어, 성능 개선, 장애 복구 후의 데이터 정합성**을 직접 재현하고 측정하는 Java/Spring 백엔드 프로젝트입니다.

## 현재 상태

기획 단계입니다(2026-10-30). 실행 가능한 코드와 실험 결과는 아직 없습니다. 문서의 수치와 시나리오는 계획이며 실적이 아닙니다.

## 핵심 질문

| 사례 | 질문 |
| --- | --- |
| 동시성 | 여러 API 인스턴스에서도 초과·중복 발급과 중복 사용을 막을 수 있는가? 제어 방식별 정확성·처리량·지연은 어떻게 다른가? |
| 성능 | 데이터와 요청이 늘 때 병목은 어디이며, 변경 전후가 동일 조건에서 수치로 어떻게 달라지는가? |
| 장애 복구 | 종료·중복 전달·컨슈머 중단 이후에도 사용·정산 결과가 정확히 한 번만 반영되는가? |

## 진행 방식

작게 동작하는 버전 → 문제 재현 → 대안 비교 → 개선 → 회귀 검증 → 기록 순서로 진행합니다. 기술은 관찰한 문제가 있을 때만 도입하고, 그 근거를 ADR로 남깁니다.

모듈러 모놀리스로 시작하며, 서비스 분리는 비동기 경계가 확인된 지점에서만 선택 실험으로 다룹니다.

## 기술 방향

- 시작: Java, Spring Boot, Spring Data JPA, 관계형 DB, 테스트 자동화, 컨테이너 기반 배포
- 단계 도입: Redis, Kafka, Outbox, (선택) Gateway·Resilience4j·분산 추적
- 구체적인 버전과 도구는 0단계에서 결정합니다.

## 한계

실제 사용자와 실제 금전 거래는 다루지 않습니다. 모든 부하·장애 결과는 통제된 실험 환경의 결과이며, 실서비스 운영 경험과 구분합니다.
