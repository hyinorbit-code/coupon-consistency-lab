# 의사결정 기록

작성일: 2026-10-30

## 확정된 방향

| ID | 결정 | 이유 |
| --- | --- | --- |
| D-001 | 쿠폰 발급·사용·정산을 실험 도메인으로 사용 | 정합성·JPA·캐시·메시징·배치를 좁은 기능에 연결 |
| D-002 | 실제 사용자 모집은 필수 아님 | 배포와 통제된 실험으로 기술적 판단을 검증 |
| D-003 | 기본 기능을 먼저 구현하고 기술을 단계 도입 | 도입 전후의 문제·근거·효과를 설명 |
| D-004 | 초기에는 관계형 DB를 정합성 기준으로 사용 | 수량·중복·상태 전이·정산의 책임을 명확히 유지 |
| D-005 | 하나의 저장소와 작은 애플리케이션으로 시작 | 완성과 실험에 집중, 필요 시 API/워커 독립 실행 |
| D-006 | 초기 저장소는 비공개 | 문서·실험을 정리한 뒤 공개 여부 별도 결정 |

D-001~D-005는 앞선 대화의 합의 방향을 문서화한 것입니다. D-006은 생성 시 적용한 초기 운영 기본값이며 사용자 요청으로 변경할 수 있습니다.

## 아직 결정하지 않은 사항

- 정확한 Java/Spring Boot 버전과 빌드 도구
- DB 제품·버전, 스키마·마이그레이션 도구
- 업무 규칙 세부 사항: PROJECT_PLAN.md 4절
- 동시성 제어: 조건부 UPDATE·비관적 락·낙관적 락 등의 비교 범위
- 인증·권한의 최소 구성
- Kafka 도입 시점, 토픽·파티션 키·순서 보장 범위, 재시도·격리 정책
- Outbox 등 DB 변경과 이벤트 발행을 연결할 방식
- Redis 사용 범위, 무효화·복구 정책
- 테스트·부하·지표 도구, 클라우드 제공자와 비용 한도
- Kubernetes 필요 여부, 일정과 주당 투입 시간

## 후속 기록 방식

주요 선택은 docs/decisions/ 아래 ADR로 작성하고 이 문서에서 연결합니다. 최초 선택과 이후 변경 이유를 보존하며, 채택/기각/대체/제안 상태를 표시합니다. 계획을 구현 완료로 표시하지 않습니다.
