# 프로젝트 계획

작성일: 2026-10-30 (Asia/Seoul)
상태: 초기 합의 방향. 업무 세부 규칙과 구현 도구는 설계 단계에서 확정.

## 1. 배경과 목적

Java/Spring 기반의 기능 개발·유지보수, SQL 개선, 배치·워커, 분석 서버 설계와 다중 서버 연동 경험을 바탕으로 일반 서비스 백엔드 포지션으로 확장합니다. 이번 프로젝트에서 보완할 영역은 JPA 모델링, Redis, Kafka, 배포 자동화, 테스트와 정량적 성능·장애 검증입니다.

실제 사용자를 모으는 것은 필수가 아닙니다. 작동하는 서비스를 배포하고 부하와 장애를 통제해 실험합니다. 실사용자 피드백이 없다는 한계는 명시합니다.

## 2. 성공 기준

- 발급·사용·취소·만료·정산 업무 규칙을 테스트로 검증한다.
- 다중 API 인스턴스에서 초과 발급과 중복 발급·사용을 방지한다.
- 중복 이벤트, 처리 중 종료, 컨슈머 중단 뒤에도 최종 정산 결과가 맞음을 검증한다.
- 병목을 측정하고 동일 환경의 개선 전후 지표와 비용을 비교한다.
- 로컬 실행·배포·부하·장애 실험을 다른 사람이 재현할 수 있다.
- 핵심 사례 문서 3개와 의사결정 기록, 정직한 README를 남긴다.

초당 처리량 같은 성능 목표는 초기 기준 측정 뒤 정합니다. 목표 수치는 측정된 성과가 아닙니다.

## 3. 최소 기능 범위

- 관리자: 캠페인, 발급 수량, 발급·사용 기간, 쿠폰 혜택 설정
- 사용자: 발급, 보유 내역 조회, 사용 요청
- 업무 처리: 중복·초과 발급 방지, 중복 사용 방지, 사용 취소, 만료
- 정산: 가맹점별 사용 내역 집계, 정산 생성과 검증
- 운영: 실패한 비동기 작업 조회·재처리, 로그와 지표

최소한의 인증·권한과 입력 검증은 포함하되 인증 플랫폼 자체를 별도 주제로 확장하지 않습니다. 실제 PG 연동, 실제 금전 지급, 전체 쇼핑몰, 추천·검색·채팅, 복잡한 프론트엔드, 다수의 마이크로서비스는 초기 범위에서 제외합니다.

## 4. 설계 전에 확정할 규칙

아래 항목은 아직 결정되지 않았습니다. 구현 전에 사례와 불변식을 작성하고 docs/DECISIONS.md에 확정안을 기록합니다.

- 사용자별 발급 제한과 발급/사용 요청의 멱등키 범위·유효기간
- 발급 취소 허용 여부와 수량 복원 여부
- 사용 취소 시 재사용 허용 여부와 만료 이후 취소 처리
- 캠페인 기간과 쿠폰 만료 시각의 경계, 저장·표시 시간대
- 정산 기준: 사용액·할인액·부담액 중 무엇을 집계하는지
- 정산 마감 시점, 늦은 취소·이벤트의 조정 정산 방식
- 상태 전이: 발급·사용·만료·취소의 허용 경로와 경합 시 우선순위
- 가맹점·사용자의 최소 권한, 실험용 계정 발급 방식

최소 불변식 후보: 발급량 ≤ 허용 수량, 사용자별 발급 제한 준수, 동일 사용의 유효 정산 반영은 한 번, 재처리 전후 최종 정산 일치. 구체적인 정의는 취소·정산 정책과 함께 확정합니다.

## 5. 아키텍처 방향

시작점은 하나의 저장소와 작은 Spring Boot 애플리케이션, JPA, 관계형 DB입니다. 도메인 책임을 나누되 불필요한 추상화·서비스 분리는 피합니다.

1. 동기 처리 기본 버전과 DB를 정합성 기준으로 구현한다.
2. 다중 API 인스턴스와 동시성 제어를 검증한다.
3. 측정된 읽기 병목에 Redis를 적용하고 무효화·장애 동작을 설계한다.
4. 후속 집계·정산·모의 알림 등의 독립 처리 필요를 확인하고 Kafka를 도입한다.
5. DB 변경과 이벤트 발행 사이의 실패를 고려한다. Transactional Outbox 등의 대안을 비교해 결정한다.
6. API와 워커의 독립 실행·확장은 필요가 생긴 시점에 도입한다.

비동기 처리를 붙였다는 이유로 API 응답을 업무 완료로 오해하지 않도록 접수·완료·실패 상태와 조회 계약을 정의합니다. 큐로 옮긴 처리의 적체와 최종 완료 지연도 측정합니다.

## 6. 단계별 진행

| 단계 | 구현·실험 | 완료 기준 |
| --- | --- | --- |
| 0. 규칙·기반 결정 | 업무 규칙, 도구·버전, 테스트 전략 | 첫 구현 범위와 ADR 작성 |
| 1. 기본 기능 | 발급·사용·취소·만료, 기본 정산 | 핵심 규칙과 API 테스트 통과, 로컬 실행 가능 |
| 2. 배포 | CI/CD, 컨테이너, 기본 로그·지표 | 검증 가능한 배포와 롤백 절차 |
| 3. 동시성 | 다중 API, 제어 방식 비교 | 초과·중복 방지 및 결과 기록 |
| 4. 성능 | 데이터 증가, SQL·인덱스·캐시 | 동일 조건의 기준·개선 지표 확보 |
| 5. 비동기 | Kafka, DB-이벤트 발행 연계, 멱등성 | 실패 모드와 중복·누락 처리 검증 |
| 6. 복구·정리 | 종료·중단·재실행, 최종 대사 | 결과 일치, 사례 3개, 재현 가이드 |

달력 일정과 주당 투입 시간은 아직 정하지 않았습니다. 각 단계의 완료 기준을 통과한 뒤 다음 단계로 넘어갑니다. 먼저 기능을 넓히기보다 실험 깊이를 확보합니다.
