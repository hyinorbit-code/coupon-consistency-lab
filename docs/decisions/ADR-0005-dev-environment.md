# ADR-0005 개발 환경: 맥북

작성일: 2026-10-30
상태: 채택
대체: ADR-0001 쟁점 3의 "개발, 테스트, 기능·동시성 정확성·장애 실험" 행

## 맥락

ADR-0001 쟁점 3에서는 Windows 노트북(메모리 32GB 이상, WSL2 + Docker)을 개발 환경으로 정했다. 실제 개발은 지금 쓰는 맥북에서 하기로 했다.

확인한 사양(2026-10-30):

| 항목 | 값 |
| --- | --- |
| 기기 | Apple M1 Pro (arm64), 8코어(성능 6 + 효율 2) |
| 메모리 | 16GB |
| 디스크 여유 | 약 205GB |
| OS | macOS 26.6 |
| 설치됨 | Temurin 21, IntelliJ IDEA, Homebrew, Git |
| 미설치 | Docker 런타임, Temurin 25, k6 |

## 결정

| 역할 | 장비 |
| --- | --- |
| 개발, 단위·통합·동시성 테스트(Testcontainers) | 맥북 |
| 전체 스택을 띄우는 로컬 실험(다중 API 인스턴스 + MySQL + Redis + Kafka + 관측 스택), k6 부하 생성기 | Windows 노트북(32GB 이상), 같은 LAN |
| 상시 배포, 공식 성능 측정 | AWS (ADR-0001 쟁점 3 그대로) |

- Docker 런타임은 메모리 사용이 적은 OrbStack을 우선 검토한다(개인 비상업 용도 무료). 완전한 오픈소스가 필요하면 Colima를 쓴다. Testcontainers는 둘 다 지원한다.
- JDK는 Temurin 25를 추가 설치하고, 프로젝트는 Gradle toolchain으로 25를 고정한다. 실무용 21은 그대로 둔다.
- Docker 런타임에 메모리 상한(약 6~8GB)을 둬서 IDE와 함께 쓸 때 스왑을 피한다.

## 근거

- 맥북은 arm64라서 로컬에서 빌드한 이미지가 EC2 Graviton(t4g·c7g)과 같은 아키텍처다. 멀티 아키텍처 빌드 없이도 로컬과 배포 환경이 일치한다.
- 메모리 16GB는 1~2단계(앱 + MySQL)와 Testcontainers 테스트에는 충분하지만, 3단계 이후 전체 스택을 한 장비에 띄우기에는 빠듯하다. 그래서 전체 스택 실험은 Windows 노트북으로 나눈다.
- Windows 노트북을 부하 생성기로 쓰면 부하 생성기와 대상 서버가 한 장비의 자원을 나눠 쓰는 왜곡을 피할 수 있다.

## 결과

- 이력서·사례 문서에 쓰는 수치는 여전히 AWS 비버스터블 인스턴스에서만 측정한다. 맥북과 Windows 노트북의 결과는 경향 확인용이다.
- ADR-0001의 상태에 쟁점 3 일부가 이 문서로 대체됐음을 표시한다.
