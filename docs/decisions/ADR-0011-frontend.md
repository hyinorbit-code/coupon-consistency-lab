# ADR-0011 프론트엔드: React 정적 SPA + CDN

작성일: 2026-10-30
상태: 채택 (구조와 프레임워크. 세부 도구는 프론트 구현 시 확정)

## 맥락

회원가입·이메일 인증·로그인·카카오 연동 화면과 E단계의 이벤트·당첨 화면이 필요하다. 프론트엔드는 범위상 "단순한 웹 페이지"이며(PROJECT_PLAN 3절), 오픈 정각에 페이지 요청이 몰리는 실전 이벤트를 견뎌야 한다. 이메일 인증 링크 주소와 토큰 보관 방식이 프론트 구조에 따라 달라진다.

## 결정

1. **React 정적 SPA**(Vite + TypeScript 예정)로 만들고, 빌드 결과를 **S3 + CloudFront**로 배포한다. 백엔드는 API만 처리한다.
2. **같은 도메인 구성:** CloudFront에서 `/api/*`는 백엔드로, 나머지는 S3로 보낸다. 브라우저 입장에서 같은 출처라 CORS가 필요 없고 쿠키 처리가 단순하다.
3. **화면은 최소한:** 회원가입, 이메일 인증 완료, 로그인, 카카오 연동, 이벤트(카운트다운·응모), 당첨(바코드·카카오톡 공유). 관리자 기능은 API와 Swagger UI로 대체한다.
4. **토큰 보관:** 액세스 토큰은 메모리, 리프레시 토큰은 HttpOnly·Secure·SameSite 쿠키(사용자 기능 3번에서 확정).
5. **이메일 인증 링크**는 프론트 주소(`couponlab.web.base-url` 설정)를 가리키고, 프론트 페이지가 `POST`로 인증을 요청한다. 프론트가 생기기 전에는 API를 직접 호출해 확인한다.
6. 프론트 코드는 같은 저장소의 `frontend/`에 둔다. 백엔드 기능을 만들 때 화면에서 흐름을 확인하기 위해 E단계보다 앞당겨 만들었다(2026-10-30).
7. 백엔드의 모든 `@RestController` 경로 앞에 `/api`를 붙인다(`ApiPathConfiguration`). Actuator는 대상이 아니다. 로컬에서는 Vite 개발 서버가 `/api/*`를 `localhost:8080`으로 프록시해 운영과 같은 단일 출처 구성을 흉내 낸다.
8. 도구: Node.js 26 LTS, Vite 8, React 19, TypeScript, React Router, oxlint(템플릿 기본). 프론트 테스트(Vitest)와 CI 연동은 화면이 늘어나면 추가한다.

## 근거

- 오픈 정각의 페이지 새로고침은 CDN이 처리하고 서버는 응모 API에 집중한다. 정적 리소스 분리는 사례 2(성능)의 근거가 된다.
- 카카오 SDK, 바코드 렌더링, 카운트다운을 구현하기 쉽고 일부 공고에서 React를 우대한다.

## 검토 후 기각한 대안

- **Thymeleaf 서버 렌더링:** 익숙하고 배포가 하나지만, 피크 때 페이지 요청까지 API 서버가 처리하고 JWT API와 쿠키 기반 페이지 인증이 섞인다.
- **정적 HTML + 바닐라 JS:** 구조상 장점은 같지만 화면이 늘수록 유지가 어렵다.
