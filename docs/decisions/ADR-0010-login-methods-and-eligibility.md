# ADR-0010 로그인 수단과 응모 자격 분리

작성일: 2026-10-30
상태: 채택
대체: ADR-0002의 "로그인: 카카오 로그인", "개인정보: 휴대폰 번호·이메일을 받지 않는다", ADR-0003 규칙 1의 참여 자격

## 맥락

실제 회원가입·로그인 로직(비밀번호 저장, 이메일 인증, 실패 잠금, 토큰 갱신, 외부 계정 연동)을 직접 구현해 보고 싶다. 반면 ADR-0002에서 정리했듯 응모 공정성은 "위조가 어려운 신원 하나당 1회"에 달려 있다. 이메일은 주소 변형(`+`, `.`)과 일회용 메일로 계정을 사실상 무제한 만들 수 있어 응모 자격의 근거가 될 수 없다.

## 결정

1. **로그인 수단은 두 가지:** 이메일·비밀번호(이메일 인증 필수), 카카오 로그인. 네이버 로그인은 하지 않는다.
2. **인증과 응모 자격을 분리한다.** 로그인은 두 수단 모두 가능하지만, **응모는 카카오 계정이 연동된 사용자만** 할 수 있다. `experiment` 프로필에서는 실험용 계정도 응모 자격을 인정한다.
3. **카카오 회원번호 하나는 사용자 한 명에게만 연동된다**(유니크 제약). 이메일 계정을 여러 개 만들어도 응모는 카카오 계정당 1회다.
4. **카카오로만 가입하는 것을 허용한다.** 연동된 카카오 계정이 있으면 그 사용자로 로그인하고, 없으면 이메일 없이 새 사용자를 만든다.
5. **이메일 가입자는 이메일 인증을 마쳐야 로그인할 수 있다.** 인증 전 계정은 대기 상태로 둔다.
6. **자동 계정 병합은 하지 않는다.** 카카오에서는 닉네임만 받으므로(ADR-0002) 이메일로 같은 사람을 추정하지 않는다. 연결은 로그인한 사용자가 직접 카카오 연동을 실행할 때만 일어난다.
7. **개인정보:** 이메일을 로그인 ID로 수집한다. 이벤트 전 개인정보 처리방침에 수집 항목(이메일, 카카오 회원번호·닉네임)과 보관·파기 기준을 반영한다. 휴대폰 번호는 여전히 받지 않는다.

## 근거

| 응모 자격으로 인정 | 한 사람이 응모 가능한 횟수 |
| --- | --- |
| **카카오 연동만 (채택)** | 사실상 1회 |
| 카카오 또는 네이버 | 최대 2회 정도 |
| 이메일 인증 포함 | 사실상 무제한 (주소 변형, 일회용 메일, 대량 가입 스크립트) |

- 경품 10개 선착순에서 이메일을 자격으로 인정하면 계정을 대량으로 만든 한 사람이 경품을 모두 가져갈 수 있다.
- 로그인 수단을 늘려도 응모 자격을 카카오로 묶으면 공부 범위(이메일 가입·인증, OAuth2, 계정 연동)는 그대로 확보하면서 공정성을 유지한다.
- 네이버는 응모 자격을 주지 않을 로그인 수단을 하나 더 유지하는 비용에 비해 추가로 배울 것이 적다(카카오와 같은 OAuth2 흐름).

## 구현 순서

| 순서 | 내용 | 외부 준비 |
| --- | --- | --- |
| 1 | V2 스키마, 이메일 회원가입, 이메일 인증(로컬은 가짜 메일 서버) | 없음 |
| 2 | 이메일 로그인, 비밀번호 해시, 로그인 실패 잠금 | 없음 |
| 3 | 액세스 + 리프레시 토큰(rotation, 재사용 탐지), 로그아웃 | 없음 |
| 4 | 카카오 로그인과 계정 연동(테스트는 WireMock) | 실제 확인 시 카카오 개발자 앱 |
| 5 | 응모 자격 검사(참여 기능 구현 때 연결) | 없음 |

## 결과

- 사용자 모델이 "사용자 + 연동 계정"으로 바뀐다. V2 마이그레이션(`V2__split_user_identities_and_add_email_credentials.sql`)으로 반영했다(ADR-0006의 "필요할 때 마이그레이션" 원칙).
  - `user_identities`: `UNIQUE(provider, provider_user_id)`, `UNIQUE(user_id, provider)`
  - `users`: 제공자 컬럼 제거, `email`(유니크)·`password_hash`·`status`·`email_verified_at` 추가. 이메일·비밀번호 동시 존재, 인증 대기는 이메일 가입자만, 활성 이메일 가입자는 인증 시각 필수를 CHECK로 강제
  - `email_verification_tokens`: 토큰 원문 대신 SHA-256 해시 저장
  - 기존 사용자는 같은 ID로 연동 계정에 옮겨지고 활성 상태가 된다(`MigrationV2Tests`로 검증). 외부 계정 첫 로그인은 사용자와 연동 계정을 한 트랜잭션에서 만들고, 동시 요청으로 막힌 쪽은 통째로 롤백된다.
- 토큰 유효기간(ADR-0007의 24시간)은 3번에서 액세스·리프레시 구조로 바꾸며 그때 새 ADR로 기록한다.
- 이 작업만큼 1단계 핵심 기능(선착순 할당)과 1차 마일스톤이 늦어진다. 회원가입·로그인 구현 경험을 얻기 위한 의도적인 선택이다.
- 다른 로그인 수단에 응모 자격을 주려면 먼저 사람 단위 식별 방법을 정하고 새 ADR로 결정한다.
