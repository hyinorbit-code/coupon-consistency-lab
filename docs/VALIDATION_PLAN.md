# 검증 계획

현재 모든 시나리오는 계획이며 실행 결과가 없습니다.

## 1. 검증 계층

- 단위 테스트: 기간·상태 전이·혜택/정산 계산 등 업무 규칙
- 통합 테스트: 실제 관계형 DB의 락·제약·트랜잭션, Kafka 전달·소비, Redis 동작
- API 테스트: 인증·권한, 유효하지 않은 입력, 중복 요청, 응답·상태 조회 계약
- 부하 실험: 동일 환경의 처리량·지연·오류·자원·정확성 비교
- 장애 실험: 종료·중단·타임아웃·중복 후 복구와 최종 대사

실제 구성 요소의 사용 방법(Testcontainers/Compose 등)은 도구 선정 시 결정합니다. 부하 생성기는 측정 대상과 자원 경합을 피하고, 그 자체가 병목인지 확인합니다.

## 2. 대표 실험

| ID | 조건·실패 주입 | 확인할 사항 |
| --- | --- | --- |
| C-01 | 예: 수량 1,000개에 요청 10,000건, API 인스턴스 2개 이상 | 발급량 상한·사용자별 제한·응답 결과와 DB 일치 |
| C-02 | 동일 사용자의 발급/사용 요청을 동시에 반복 | 중복 발급·중복 사용 없음, 일관된 응답 |
| C-03 | 사용·취소·만료를 경계 시각에 경합 | 확정한 상태 전이와 정산 정책 준수 |
| P-01 | 데이터 규모·조회 빈도 단계 증가 | 실행계획, 느린 쿼리, N+1, 연결 풀과 자원 병목 |
| P-02 | 인덱스·조회·캐시 변경 전후 | 동일 조건의 p95/p99·처리량·오류율·DB 부하 |
| F-01 | DB 저장 직후 이벤트 발행 전 프로세스 종료 | 복구 후 후속 작업 누락 없음 |
| F-02 | 이벤트 발행 직후 처리 완료 표기 전 종료 | 중복 발행에도 사용·정산 중복 반영 없음 |
| F-03 | 소비자의 DB 반영 직후 오프셋 확인 전 종료 | 재전달 후 최종 데이터 동일 |
| F-04 | 컨슈머 중단 후 재기동 | 적체 해소 시간, 최종 완료 지연, 누락·중복 |
| F-05 | 처리 불가능한 이벤트와 일시 오류 | 제한된 재시도, 실패 격리, 원인 조회·재처리 |
| F-06 | 정산 배치 중간 실패와 재실행 | 기준 원장과 집계 일치, 중복·누락 없음 |
| F-07 | Redis 중단·만료·캐시 무효화 경합 | 정의한 fallback·정확성·지연·DB 부하 |

요청 10,000건 등의 수치는 실험 예시입니다. 실제 규모는 장비·비용·실행 시간을 고려해 결정합니다. Kafka 관련 실험은 해당 단계가 구현된 뒤 실행합니다.

## 3. 필수 측정값

- 정확성: 발급 수량, 중복 수, 상태별 건수, 누락 수, 기준 원장과 정산 차이
- 요청: 유입량, 성공/거절/실패별 처리량, p50/p95/p99, 타임아웃·오류율
- 비동기: consumer lag, 재시도·격리 수, 이벤트부터 최종 완료까지 지연, 복구 소요 시간
- 자원: CPU·메모리, GC, DB 연결·락 대기·느린 쿼리, 캐시 적중률, 네트워크·저장량
- 비용: 서버 수·사양·실행 시간, 클라우드 사용 시 실험 비용

빠른 거절 응답을 성공 처리 성능과 섞지 않습니다. 비동기 접수 응답이 빨라졌다는 이유로 업무 처리량이 증가했다고 판단하지 않습니다.

## 4. 재현성

각 결과에 OS/JDK/애플리케이션/DB/브로커 버전, 커밋 SHA, CPU·메모리·인스턴스 수, 데이터 생성 seed와 규모, 요청 분포, 워밍업·실험 시간, 반복 횟수, 명령과 원시 결과 위치를 남깁니다.

비교 실험은 한 번에 주요 변수 하나를 변경합니다. 초기 탐색 후 본 측정은 가능한 범위에서 3회 이상 반복하고 중앙값·편차·이상치를 함께 기록합니다. 조건이 달라진 결과는 별도 실험으로 표시합니다.

결과 파일에는 비밀값과 실제 개인정보를 넣지 않습니다. 큰 원시 결과를 Git에 무조건 커밋하지 않고, 소형 요약과 재현 스크립트·보관 위치를 남깁니다.

## 5. 핵심 사례 완료 조건

문제와 가설, 재현 스크립트, 기준 결과, 선택한 대안, 개선 결과, 정확성 회귀 검증, 한계, 연결된 코드/커밋이 있어야 완료로 간주합니다. 실패한 가설도 원인을 설명하면 유효한 결과입니다.
